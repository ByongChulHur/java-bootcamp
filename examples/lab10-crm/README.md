## CI note (preview — pipelines deepen in later modules)

Preferred verify command on agents:

    mvn -B verify

`-B` is batch mode (non-interactive). Prefer `verify` over `install` on CI
unless your pipeline intentionally publishes to an artifact repository.
Never deploy snapshots from a developer laptop without agreement.

## Security and Production Review
1. Which parts of a Copilot prompt are untrusted from the model’s perspective, and which are trusted (your business rules)?
All prompt text that is generated by Copilot is not be trusted until people review themselves.
The business rules and coding standards that you write are trusted, because they are written by humans and reviewed by humans.

2. Where is human review formally enforced before AI code reaches the shared repo?
Human review is formally enforced through a mandatory checklist which I did in step 7
that must be completed before any AI-generated code can be merged into the shared repository.

3. Which values must never appear in Chat, even as examples?
All values that mus not appear in Chat such as real customer id, real SSNs, and passwords. We need to use fixture ID such as
CUs-1001, CUS-1002, and lab-request-001 for correlation ID.

4. What can be safely regenerated if rejected, and what must a human write from scratch?
All the boilerplate code and test code can be safely generated. All the Business logic and rules must be understood and if it is wrong
then it have to be fixed by human.

5. What if an AI-suggested dependency only fails in CI mvn compile, not locally?
If it only fails in CI mvn compile and not locally then it means that environment mismatch is causing the issue.


6. What would a tech lead audit to confirm AI-assisted code met the same bar as hand-written code?
the ai-review-notes.md log itself — whether phantom dependencies were caught, whether the developer can 
explain the code unaided, and whether business rules are actually enforced in code, not just described in comments.

7. Which licensing/IP concern applies to large verbatim-looking suggestions, and how do you mitigate it?
Mitigate by keeping prompts scoped being suspicious of usually long or unique suggestions. 
If these suggestions are used, then we need to check the license of the source and make sure it is compatible with our project.

8. How do you keep an audit trail of what a human verified vs what the AI produced?
honestly it's just the ai-review-notes.md file. Every time I logged what prompt I used, what came back, whether I
accepted/rejected/partially fixed it, and why. So anyone reading it later can tell what I actually checked versus what the AI just gave me.
